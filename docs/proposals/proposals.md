# Proposals

A document lands here when it argues for a change rather than describing
what thorn already does — a word the profile should admit, a gesture the
core should have, a boundary it should keep — and may lose the argument.
The argument for this repository's existence is the org's proposal, *A
drawing editor over twig's SVG, as its own repository*, and stays there.

Each carries `status` in its frontmatter — `draft`, `accepted`,
`implemented`, `deferred`, `rejected` — which `dx tasks` reads. The list
above holds every proposal, resolved or not: the index is the spine, and
what is unresolved is a view of it. Closing one is an edit that names the
commit or release that resolved it, with the outcome in a **Status** section
at the top and the body left as argued, because the reasoning is the value
even when it lost.

What this is not: a commitment to consumers, which goes in the changelog's
unreleased region; a description of what shipped, which goes in the READMEs
and `docs/profile.md`; or deferred work with a done state, which is a task.
